###############################################################################
###### 1단계 :  서버 dev 브랜치를 릴리즈 브랜치 TBIB60004 에 병합하고, push로 올리기 ###########
###############################################################################

1. 작업 폴더 이동, 수정 파일 없는지 확인
cd /d D:\tbi-batch-shell
git status

2. 서버 최신 정보 받기, --prune 으로 삭제 브랜치 있으면 정리까지 (dev, TBIB60004 사진 갱신)
git fetch --prune

3. 릴리즈 브랜치로 이동하고 서버 릴리즈와 맞추기
git switch TBIB60004
git pull

4. 서버 dev 내용을 릴리즈에 합치기 (내 PC에서) - 2번 fetch 까지만
git merge --no-ff origin/dev -m "TBIB60004: dev 반영 (a.py, b.py, c.py)"

    --no-ff는 **”fast-forward(앞으로 건너뛰기) 하지 말고, 반드시 병합 커밋을 만들어라"**라는 옵션
    없으면 언제 병합했는지 모름, 언제 dev를 릴리즈에 반영했는지" 흔적을 남기기 위해 사용

5. 서버 릴리즈에 올리기  ← 여기까지가 "릴리즈에 올리기"
git push origin TBIB60004

## 2단계 :  IQ+ 스테이징 배포를 요청하기 전에, stg 커밋 이력을 릴리즈(TBIB60004)에 사전 병합하기 ######
##################################################################################

1단계. 준비
cd /d D:\tbi-batch-shell
git status
git fetch --prune
git switch TBIB60004
git pull

   -> 1단계가 끝나면 로컬에 서버 origin/stg 최신 상태정보가 PC에 저장되고,
       로컬에 TBIB60004 이동(또는 생성 후 이동) 된 후 서버 TBIB60004 브랜치의 최신 정보를 받아옴

2단계. 병합이 필요한지 확인
   : 로컬에 저장된 서버 origin/stg 최신 상태 정보와 서버에서 받아온 로컬 TBIB60004 브랜치 최신 정보를 비교하여
     병합이 필요한지 확인함.

git merge-base --is-ancestor origin/stg TBIB60004 && echo 이미포함 || echo 병합필요
   -> 결과가 이미포함 이면 6단계로 가서 재확인 후 IQ+로 스테이징 배포요청, 아니면 3단계로

3단계. stg에만 있는 것 미리 보기
 1) stg에만 있는 커밋 목록
    git log --oneline TBIB60004..origin/stg
       : stg에는 있고 릴리즈(TBIB60004)에는 없는 커밋 목록을 커밋하나를 한 라인으로 출력
         결과가 없으면 병합 불필요. stg에만 있는 커밋이 있는 경우는 병합필요

 2) 병합하면 릴리즈로 들어올 파일 차이  (위 결과가 있을때)
    git diff --name-status TBIB60004...origin/stg
       : stg와 릴리즈가 갈라진 이후, stg 쪽에서만 바뀐 파일 목록 출력, 병합될 파일 확인
         결과가 없으면 stg 쪽 커밋은 있지만 파일 변화 없음으로 병합해도 릴리즈 코드는 안 바뀜
         @@@ 이 경우가 IQ+ 자동 병합 커밋 등 이력만 있는 경우로 가장 흔한 경우임
         파일이 나오면 병합하면 이 변경이 릴리즈로 들어올 수 있으므로 무엇인지 확인 필요

4단계. stg 이력을 릴리즈에 병합 (공지 내용)
git merge origin/stg -m "TBIB60004: stg 커밋 이력 merge"
  -> 결과에 따라 분기
         Merge made by the 'ort' strategy.  -> 5단계로
         Already up to date. -> 이미 포함됨. 6단계로
         CONFLICT ->  충돌 시로 CM 신청자에게 통지 및 공유

5단계. 들어온 내용 확인 후 올리기
 1) 병합 전 릴리즈와 비교해서 바뀐 파일
     git diff --stat HEAD~1 HEAD
       -> 결과가 비어 있음 : 이력만 연결됨. 코드 변화 없음 → 바로 push
           파일이 보임 : stg 내용이 릴리즈에 들어옴. 운영 배포에도 함께 나가므로 필요한 내용인지 확인 후 push
 2) git push origin TBIB60004
    -> xxxxxxx..yyyyyyy TBIB60004 -> TBIB60004가 보이면 성공

6단계. 최종 확인
git fetch
git merge-base --is-ancestor origin/stg origin/TBIB60004 && echo 해결됨 || echo 미해결
  -> 해결됨이 나오면 서버 릴리즈에 stg 이력이 모두 포함된 것이고, 이제 IQ+에서 스테이징 배포 요청

## 3단계 :  IQ+ 스테이징 배포를 요청하기 전에, stg 커밋 이력을 릴리즈(TBIB60004)에 사전 병합하기 ######
##################################################################################


cd /d D:\tbi-batch-shell
git status
git fetch --prune
git switch TBIB60004
git pull
git diff --stat origin/stg origin/TBIB60004    ## 선택적인 명령으로 스테이징 테스트 후 누군가 릴리지 배포했는지 확인용
git merge-base --is-ancestor origin/prd TBIB60004 && echo 이미포함 || echo 병합필요
:: ── 병합필요일 때만 ──
git log --oneline TBIB60004..origin/prd
git diff --name-status TBIB60004...origin/prd
git merge origin/prd -m "TBIB60004: prd 커밋 이력 merge"
git diff --stat HEAD~1 HEAD
git push origin TBIB60004
:: ── 최종 확인 ──
git fetch
git merge-base --is-ancestor origin/prd origin/TBIB60004 && echo 해결됨 || echo 미해결

## TIP) stg, prd에 실제 변경 코드가 있을때, 내용을 모두 삭제하고 내 릴리즈 기준으로 병합하고 싶을때 ######

git merge -s ours origin/stg -m "TBIB60004: stg 이력 연결 (stg 내용 미반영)"

git push origin TBIB60004
